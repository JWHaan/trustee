# Deploying the Trustee arena

A one-time runbook. Work top to bottom and tick each box. Secrets go into `.env` (gitignored) locally and
into Render's dashboard for the hosted service. Never paste a secret, password or token into the repo,
an issue, a commit message or the Devpost text.

Assumed values, replace them if yours differ:

- Repo: `JWHaan/trustee`, branch `main`
- Render service: `trustee-arena`, so the public URL is `https://trustee-arena.onrender.com`

---

## a. PayPal Developer Dashboard (sandbox)

- [ ] Sign in at https://developer.paypal.com and open **Apps & Credentials**. Make sure the **Sandbox** toggle is on.
- [ ] Click **Create App**, pick a name such as `trustee-arena`, and choose the Business account type.
- [ ] Copy the **Client ID** and **Secret** shown for the sandbox app. You need them in steps b and d.
- [ ] Open **Testing Tools → Sandbox Accounts**. Two default accounts exist:
  - a **business** account: the seller and payee. Its email goes into `--seller-email` in step b;
  - a **personal** account: the buyer that approves payments. Click the account, then **View/Edit**, to find its login email and password.
- [ ] Store those sandbox logins in your password manager. Do not write them into the repo.

## b. Local proof first

Run the real sandbox flow on your machine before you deploy anything.

- [ ] Copy the template and fill in the sandbox values:

  ```bash
  cp .env.example .env
  # edit .env: PAYPAL_CLIENT_ID, PAYPAL_CLIENT_SECRET, and PAYPAL_ENV=sandbox
  ```

- [ ] Settle path. The script creates an order, prints an approve URL, waits for approval, authorizes, then captures to the seller:

  ```bash
  set -a; source .env; set +a
  uv run python examples/sandbox_poc.py --settle --seller-email <sandbox-business-email>
  ```

- [ ] Open the printed approve URL in a browser. Log in with the **personal** sandbox account and approve.
- [ ] Success looks like: the script prints an authorization id, then a capture id, then exits 0. Check the
  order in the sandbox account's transaction list; it shows as completed.
- [ ] Refund path, same steps with a fresh order. The void releases the hold and the buyer keeps the funds:

  ```bash
  uv run python examples/sandbox_poc.py --refund --seller-email <sandbox-business-email>
  ```

- [ ] A dry run needs no credentials and no network. Use it to check the steps before you have creds:
  `uv run python examples/sandbox_poc.py --dry-run`.

The script refuses to run with `PAYPAL_ENV=live`. It never prints credentials or tokens.

## c. NVIDIA NIM (LLM)

- [ ] Sign in at https://build.nvidia.com and create an API key. Keep it in your password manager.
- [ ] Model: `nvidia/nemotron-3.5-lightning-30b-a3b` with thinking off (`LLM_EXTRA_BODY`), endpoint
  `https://integrate.api.nvidia.com/v1` (the defaults in `.env.example`).
- [ ] Put the key in `.env` as `LLM_API_KEY`. With the key empty, the arena runs in scripted mode. The money path
  still runs, but the chat is replayed from recorded moves.

## d. Render

- [ ] In Render, choose **New → Blueprint** and connect the GitHub repo `JWHaan/trustee`.
- [ ] Set the branch to `main`. Render reads `render.yaml` from the repo root.
- [ ] Fill in the `sync: false` secrets on the blueprint form:
  - `LLM_API_KEY`
  - `PAYPAL_CLIENT_ID`
  - `PAYPAL_CLIENT_SECRET`
  - `PAYPAL_WEBHOOK_ID` (you can leave it blank for now and fill it in during step e)
- [ ] `TRUSTEE_OPERATOR_TOKEN` is generated by Render. Copy it from the service's **Environment** tab into your
  password manager. You need it for `POST /v1/deals/{id}/resolve` and for registering principals.
- [ ] Click **Apply** and wait for the build. The first deploy takes several minutes because the image builds the UI.
- [ ] Confirm the public URL. If Render assigned a host other than `trustee-arena.onrender.com`, change
  `TRUSTEE_PUBLIC_URL` in the service's Environment tab to the real `https://<host>` and redeploy. This value
  sets the Agent Card URL and the PayPal return/cancel URLs.
- [ ] Verify the service:

  ```bash
  curl -fsS https://trustee-arena.onrender.com/healthz
  # expect "paypal":"sandbox" and "store":"in-memory"
  curl -fsS https://trustee-arena.onrender.com/.well-known/agent.json
  # expect the Agent Card JSON
  ```

- [ ] Open `https://trustee-arena.onrender.com/` in a browser and confirm the arena UI loads.

Free-tier notes: the service sleeps after 15 minutes idle, and the first request after a sleep can take about
50 seconds. The platform store is in-memory, so a restart forgets platform deals. Anything PayPal already
authorized expires on its own in the sandbox.

## e. PayPal webhook

- [ ] In the sandbox app's **Webhooks** section, click **Add Webhook**.
- [ ] Webhook URL: `https://<render-url>/v1/paypal/webhook` (for example `https://trustee-arena.onrender.com/v1/paypal/webhook`).
- [ ] Subscribe to these event types:
  - `CHECKOUT.ORDER.APPROVED`
  - `PAYMENT.AUTHORIZATION.VOIDED`
  - `PAYMENT.CAPTURE.COMPLETED`
  - `PAYMENT.CAPTURE.DENIED`
  - `PAYMENT.CAPTURE.REVERSED`
  - `PAYMENT.CAPTURE.REFUNDED`
- [ ] Save, then copy the **Webhook ID** shown on the webhook's detail page.
- [ ] In Render, set `PAYPAL_WEBHOOK_ID` to that id and redeploy. Every delivery is verified with PayPal against
  this id. A mismatched id makes the server return `400` on every webhook.
- [ ] Do not set `TRUSTEE_WEBHOOK_ALLOW_UNVERIFIED` on the hosted service. It exists for local dev only.

## f. Keep-alive

- [ ] In the GitHub repo, go to **Settings → Secrets and variables → Actions → Variables** and add
  `TRUSTEE_DEMO_URL` = `https://trustee-arena.onrender.com` (no trailing slash). This is a variable, not a secret.
- [ ] Go to **Actions → keepalive → Run workflow** and run it once by hand. The run should pass and print the
  `/healthz` JSON.
- [ ] Scheduled runs happen every 10 minutes from the default branch. GitHub can delay them, and it disables
  scheduled workflows after 60 days without repo activity (see `.github/workflows/keepalive.yml`).

## g. Judge access

- [ ] Put the demo URL in the Devpost submission: `https://trustee-arena.onrender.com`.
- [ ] Create a **dedicated** sandbox personal (buyer) account for judges. Do not share your default one. Use the
  Sandbox Accounts page to create it, then give judges its login for the approval step only. Sandbox accounts hold
  fake money, but a separate account keeps your own sandbox profile out of it.
- [ ] Tell judges the approval step: the arena shows an approve URL. Log in with the dedicated sandbox buyer account and approve.
- [ ] After judging, delete the dedicated sandbox account and rotate `TRUSTEE_OPERATOR_TOKEN` in Render. Also rotate
  `PAYPAL_CLIENT_SECRET` in the PayPal app and `LLM_API_KEY` at build.nvidia.com if you shared those with anyone.

## h. Troubleshooting

| Symptom | Cause and fix |
|---|---|
| `401` on `POST /v1/principals` or `/resolve` | The bearer token is missing or wrong. Read `TRUSTEE_OPERATOR_TOKEN` in the Render Environment tab and send it as `Authorization: Bearer <token>`. |
| `422 ORDER_NOT_APPROVED` on authorize | The payer has not approved the order yet. Open the approve URL and approve as the sandbox buyer. The sweep retries automatically. |
| First request takes about 50 s, or the UI shows "warming" | Cold start on the free plan. Keep-alive (step f) prevents this between pings. |
| Webhook returns `400` | `PAYPAL_WEBHOOK_ID` does not match the webhook you subscribed. Copy the id again and redeploy. Also check that the event types in step e are subscribed. |
| `/resolve` returns `403` | `TRUSTEE_OPERATOR_TOKEN` is not set on the server. Set it in Render. |
| `"paypal":"dry-run"` in `/healthz` | `PAYPAL_CLIENT_ID` or `PAYPAL_CLIENT_SECRET` is empty on the service. Fill both in Render. |
| Return or cancel URL goes to the wrong host | `TRUSTEE_PUBLIC_URL` does not match the real service URL. Fix it and redeploy. |
